# Roadmap

Goal: play Yu-Gi-Oh! ONLINE 3 with friends on our own server. Each milestone ends in something checked against the
real client (`tools/client/vclient.sh`), not just against tests. Tick boxes in the same commit as the work.

This page says what is open and what comes next. Three other pages hold the rest:

- [Features](features.md): what works today, area by area, with how each row was verified.
- [History](history.md): the dated records (release preparation, investigations, sessions) and milestones M0 to M6.
- [Protocol](protocol.md): every request and reply, with its client evidence.

Platform scope: **64-bit Windows 10/11** and **Linux with Wine**. Windows 7 is out of scope for now, for both Desktop
and Scripts; players can use VxKex at their own risk ([launcher](launcher.md#windows-7)).

## Open now

**Standalone management dashboard**

      timing, and the DNS-based HTTPS monitor after resolver caches expire. Choose off-machine backup storage and
      alert destinations. Completed provisioning, recovery and protocol checks: [VPS record](history.md#2026-11-17--public-vps-deployment-and-recovery).
- [ ] Normalize SQLite domains incrementally after deployment validation; keep the generated API unchanged.

**Duels**

- [ ] Complete menu/effect coverage and automatic native UI replay/minimization. Known reveal/reversal/disabled-zone
      gaps remain visible; neither the random corpus nor matching state hashes proves all card interactions.
- [ ] Anime card versions (#60, off by default): 415 of 418 reviewed cards play as ProjectIgnis' anime versions with the
      `anime-cards` setting on ([list](anime-cards.md)), and the game shows them through the card profile; every category of
      difference is released (`PROFILE_COVERS` in `tools/engine/anime-map.py`). Time Wizard, Thousand Dragon and Temple of the Kings
      keep the game's version on purpose. Windows 11 checks passed on 2026-11-20 (stats, types, text, sorting and ranges, art
      folder and the missing-picture fallback, deck migration both ways, the restart button and the refusal of a stale game, an
      NPC duel with the duel check clean: [features](features.md)). Open: the anime pictures in a duel's hand and field on
      Windows, effect accuracy against the episodes. The `anime-cards` setting becomes the default only after that.
- [ ] Issue #7 stays open for whatever players find next: the scripted pass catches limits, numbers and ProjectIgnis'
      known pre-errata cards, not every ruling.
- [ ] Watched, not reproduced: a monster's switch to Defense Position at the end of the Battle Phase (Goblin Attack
      Force) stayed drawn upright on its owner's screen once, in a duel with Pegasus' Toons; six tries since showed it
      sideways every time, so the trigger is unknown (details in [history](history.md#status)).
- [ ] Not seen live: a Deck rental's three lists, a card's own string as a duel hint, a card's own Yes/No line.
- [ ] Choosing a duel's opening track (`duel_id % 8`, `event_type` 5) is server-side and not built.

**Titles**

- [ ] Titles not earned yet: KING OF DESTRUCTION (meaning unclear), MR. 1 TURN SURRENDER, MARITIME PILOT (invites), the
      second Jaden titles (TRUE JADEN FAN, MAGNET FOR DESTRUCTION, THE SEEKER OF TRUTH), Téa's and Jim's (not NPCs
      here), and the event and Championship ones (below).

**Windows and hosting verification**

- [ ] Native Windows 10, protected-folder direct-start installation, runtime reinstallation and separate-machine
      network checks remain open; Windows 11 evidence does not close those items.
- [ ] Native Windows protected-folder/UAC behavior, friends on separate machines and the first published GUI-to-GUI
      automatic update still need platform/release verification. Firewall mutation is outside the launcher's scope.
- [ ] Player verification of real GitHub sign-in and issue/Gist publishing, including native Windows credential storage.
      HTTP/vault checks used mocks; no player diagnostics were uploaded during development.
- [ ] The Discord recording's native game exit `0xc0000005` is a separate failure. A crash dump or faulting address from
      a failing machine is still needed; seven fresh native Windows 11 launches did not reproduce it.

**Higher resolution**

- [ ] A Japanese or Korean IME, a second monitor.
- [ ] Direct start: the DLL loads after the window exists, so `yo3.exe` opened directly stays 1024×768. The WINMM
      loader would have to install the window and Direct3D hooks itself.
- Out of scope: true 16:9 (every screen laid out again).

## Later, with a public server and enough players

The public beta itself (a player launcher, password accounts, a hosted server with remote administration) is tracked
in GitHub issue [#20](https://github.com/usersina/yo3-revival/issues/20) and its sub-issues: the decisions, the order of
work, and each part's spec and edge cases.

The "Website links, titles and official events" plan (2026-11-15) split its work into what any server can do now (done,
in [history](history.md#-website-links-titles-and-official-events-planned-2026-11-15)) and these, which only make sense
with many players. GitHub issue #16 tracks convenience features, #17 the Championship and #18 Official Events.

- Done and moved to [features](features.md): the leaderboard and team ranking (#16), and the Stadium's Official Events
  (#18). Still open from #18: the original's Special Pack prizes, the Ultimate Match against the computer (only players
  are paired), the official-event titles (TRIALIST … ULTIMATE GUNSLINGER) and the real thresholds.
- [ ] The Championship (Tournament Map): a host-scheduled `event_type` 10 event on the user-event bracket code, with the
      `0x32FB` Championship fields and the draw pushes; a 512-seat preliminary needs far more players than a small
      server has (a smaller block count, guess). Y.O.C WINNER / FINALIST.
- Not possible: the map's UNIZAWA and market tiles (`btn5`, `btn6` have no handler in `main.swf`).
- The client's research notes for these (the three scenes, `0x177B` and `0x32FB` fields, Konami's logs) are in the
  [plan's record](history.md#-website-links-titles-and-official-events-planned-2026-11-15).
